# Architecture and integration guidance

Optional reference for the feature owner; this legacy filename assigns no role.
Read the task, affected dependencies and current project rules. Keep one concrete
goal and record decisions with their reasons. Avoid broad audits or refactors
without a task requirement.

Check the exact baseline and candidate before integration. Distinguish reported
results, self-review, automated verification and independently requested review.
Preserve useful evidence from historical packages without treating their mandates
as current instructions. CI success does not expand the user's assigned scope.

Keep the task checkpoint current; update shared PROJECT_STATE only with supported
status changes. Reconcile concurrent changes without dropping either feature.
Follow [the feature workflow](../project/FEATURE_WORKFLOW.md) for acceptance and
archiving. A short GitHub checkpoint normally replaces manual role handoffs;
export packages when useful.
